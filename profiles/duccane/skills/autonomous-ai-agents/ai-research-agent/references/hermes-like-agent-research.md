# Hermes-like Agent & Low-Code Noise Research Notes

Use this reference when operating Hakan-style research agents for Botfusions market intelligence.

## Durable observations

- X/Twitter often collapses Zapier, Make, and n8n workflows into the phrase “AI agent.” Treat these as low-signal unless the post demonstrates autonomous planning, memory, evaluation, safety controls, or production deployment.
- n8n can be more relevant than Zapier/Make when paired with LangChain/MCP/custom code, but the research agent should not equate a workflow builder with a full agent operating system.
- Hermes/Hermes-like demand is its own track: self-hosted/local agents, multi-agent profiles, persistent memory, safety guardrails, cost tracking, evaluation loops, and setup/consulting requests.
- The Botfusions angle is not “we automate zaps”; it is “we install and operate measurable agent systems” using concepts like Loop Engineering, EFC quality metrics, ECC safety hardening, Lemma memory, and wiki-backed reporting.

## Suggested query families

- `"Hermes Agent" OR "self-hosted AI agent" OR "local AI agent"`
- `"AI agent setup" OR "agent operating system" OR "multi-agent framework"`
- `"Loop Engineering" OR "agent evaluation" OR "agent memory"`
- `"Zapier" "AI agent"` and `"n8n" "AI agent"` only as market-noise/positioning checks, not as primary technical sources.

## Classification rule

When reporting posts/articles, label each item as:

- **High signal:** contains implementation detail, architecture, evaluation, safety, memory, production metrics, or setup demand.
- **Medium signal:** explains a real tool capability but lacks evaluation/deployment proof.
- **Low signal:** generic hype, “n8n/Zapier makes agents” claims, listicles, or no concrete workflow beyond trigger-action automation.
